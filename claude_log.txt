Sure. Here's a top-down walkthrough of the whole project.

The big picture
The program asks: "How well does bootstrap resampling estimate standard errors and confidence intervals, across distributions of different shapes?" It answers by running a simulation — drawing thousands of samples, bootstrapping each one, and recording how accurate the estimates are.

internal/stats — the math primitives
This is the foundation everything else builds on. It provides four simple statistical functions:

Mean — sums all values and divides by n
Median — sorts the slice, then picks the middle value (or averages the two middle values for even n)
Variance / StdDev — sample variance using Bessel's correction (divides by n−1, not n), which gives an unbiased estimate
Quantile — given a sorted slice, returns the value at a given percentile using linear interpolation; this is used to cut the tails off bootstrap distributions to form confidence intervals
Nothing in here knows about bootstrapping or distributions — it's purely arithmetic.

internal/distrib — distribution generators
This package creates random samples from three distribution shapes, all carefully tuned to share the same theoretical mean (100) and standard deviation (10) so comparisons between shapes are fair:

Symmetric — plain rnorm, draws from a normal distribution directly
Positively skewed — log-normal; the key insight is that if you exponentiate a normal draw you get a right-skewed result. The DeriveLogNormal function works backwards from the target mean/SD to find the correct meanlog and sdlog parameters
Negatively skewed — reflects the log-normal by computing (2 × mean) − X, which flips the long tail to the left side while keeping the mean and SD identical
Every generator accepts a *rand.Rand backed by the MT19937 source, so the caller fully controls the random seed.

vendor/github.com/seehuhn/mt19937 — the random number generator
Rather than using Go's default PRNG, the project uses the Mersenne Twister (MT19937-64). This is the same algorithm R uses internally, which makes results more directly comparable to the original R code.

The key API is simple:

go
mt  := mt19937.New()   // allocate
mt.Seed(42)            // seed it
rng := rand.New(mt)    // wrap in standard rand.Rand
After that, rng behaves like any normal *rand.Rand — calling .NormFloat64(), .Intn(), etc. — but the underlying numbers come from MT19937 instead of Go's built-in generator.

internal/bootstrap — the core resampling engine
This is the heart of the project. Run(x, B, alpha, rng) does the following for a single observed sample x:

Resample — draws B bootstrap samples from x with replacement using rng.Intn(n) to pick random indices
Compute statistics — for each bootstrap sample, records the mean and median
Estimate standard errors — takes the standard deviation of all B bootstrap means (and medians); this is the bootstrap SE
Build confidence intervals — sorts all B bootstrap means, then cuts at the alpha/2 and 1−alpha/2 percentiles; this is the percentile bootstrap CI
The key idea: the spread of bootstrap statistics across resamples approximates the spread you'd see if you could actually repeat the original study many times.

internal/permtest — simulation-based hypothesis testing
Implements a permutation test to ask: "Could two samples have come from the same distribution?"

The logic:

Compute the observed difference in means between group X and group Y
Pool all observations together, then randomly shuffle and re-split into two groups of the original sizes — repeat this reps times
Count how often the shuffled difference is at least as extreme as the observed one
That proportion is the two-sided p-value
Because the two distributions (positive-skew and negative-skew) are constructed to have the same mean, H₀ is actually true, so the rejection rate should hover near alpha (5%). This verifies the test is calibrated correctly.

internal/logging — structured logging
A thin wrapper around Go's standard log/slog package. It adds:

Level control — Debug, Info, Warn, Error; debug mode also prints the source file and line number
Format switching — plain text (default) or JSON (useful for piping to jq or log aggregators)
Convenience functions — logging.Info(...), logging.Debug(...) etc. so other packages don't need to import slog directly
Every significant event in the simulation — cell completion, distribution start, permutation test result — is logged with structured key-value pairs like n=100, avgBootSEMean=0.995, elapsed=117ms.

cmd/bootstrap/main.go — the study loop
This is where everything connects. The flow is:

parse flags → init logger → start CPU profiler (optional)
    │
    └─ for each distribution shape (pos-skew, symmetric, neg-skew):
           └─ for each sample size n in [25, 100, 225, 400]:
                  └─ repeat N_ITER times:
                         draw sample → bootstrap it → record SE and CI hit/miss
                  → average results across iterations → print and log
    │
    └─ permutation tests (pos-skew vs neg-skew, n=25 and n=100)
    │
    └─ print summary tables
    └─ write memory profile (optional)
The outer loop (iterations) is what turns this from a single estimate into a simulation — by repeating the whole process 200 times per cell and averaging, you get stable estimates of how bootstrap performs on average, not just for one lucky or unlucky sample.

The summary tables at the end compare four SE estimates side by side:

CLT SE — the theoretical σ/√n, only valid for the mean of a normal distribution
Simulation SE — the true empirical SE, computed as the SD of sample means across all iterations
Bootstrap SE — what the bootstrap estimated on average
Median SE — bootstrap SE for the median, which has no simple closed-form equivalent to the CLT
